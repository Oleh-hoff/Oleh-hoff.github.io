# Amazon CRM

Дашборд аналитики Amazon на GitHub Pages. Меню слева, рабочая область справа.

Разделы: **Проверка аккаунта** (состояние по одиннадцати пунктам),
**Продажи по неделям** (три месяца в разрезе площадки и товара) и
**Вики** (база знаний проекта).

**Адрес:** https://oleh-hoff.github.io/

## Вход

Логин `oleh`, пароль задаётся в `assets/js/auth.js` (хранится не сам пароль,
а производная PBKDF2-SHA256, 150 000 итераций).

Сменить: открыть `tools/password.html`, ввести новый пароль, полученную
строку вставить в массив `users` файла `assets/js/auth.js`, закоммитить.

## Что здесь публично

Репозиторий публичный — иначе GitHub Pages на тарифе Free не работает.
Отсюда следует:

- **`data/finance.json` открыт по прямой ссылке.** Форма входа защищает
  страницу, но не файл: выручку, комиссии и маржу увидит любой, кто откроет
  адрес файла напрямую.
- Проверка логина выполняется в браузере посетителя, поэтому её можно
  обойти, открыв `app.html` напрямую.

Секреты SP-API при этом закрыты: они лежат в Actions secrets, их нет ни в
коде, ни в логах, и рабочим процессам из форков они недоступны.

Если публичность данных не устраивает — данные можно шифровать AES-256-GCM
ключом из пароля входа. Тогда по прямой ссылке будет нечитаемый набор байт,
а всё остальное останется как есть.

## Автоматизация

`.github/workflows/amazon-sync.yml` — каждые 4 часа забирает новые проводки
из SP-API, обновляет `data/finance.json` и коммитит. Pages пересобирает сайт
сам, поэтому цифры на дашборде обновляются без участия человека.

Режимы запуска вручную (Actions → Run workflow):

| Режим | Что делает |
|---|---|
| `incremental` | добрать новое с последней отметки — минуты |
| `resume` | продолжить сбор истории с места обрыва, пять окон за заход |
| `full` | заново с начала года — часы |

История собирается заходами `resume`: лимит Finances API — 0,5 запроса в
секунду, за год набирается около четырёх тысяч страниц. Один заход берёт
пять окон по 15 дней и коммитит результат, поэтому прерывание стоит не
больше одного окна.

## Данные

**Проводки** — Finances API. Выручка и комиссии приходят из одних и тех же
событий, поэтому сходятся между собой.

**Продажи по товарам** — отчёт по заказам
(`GET_FLAT_FILE_ALL_ORDERS_DATA_BY_ORDER_DATE_GENERAL`). Отчёт отдаёт максимум
30 дней за запрос, поэтому квартал берётся четырьмя отчётами. Родитель товара
у Amazon свой на каждой площадке, поэтому вариации сшиваются в семьи.

Статьи расходов: Referral Fee, логистика FBA, размещение запасов, хранение,
поставка на склад и пошлины, реклама, купоны и акции, прочие сборы,
возвраты, возмещения Amazon. Незнакомый тип не теряется — попадает в
«прочее» под своим именем и печатается списком в конце запуска.

Суммы по умолчанию не пересчитываются между валютами: курса в данных Amazon
нет, а взятый со стороны не сойдётся ни с Seller Central, ни с банковской
выпиской. Валюта выбирается фильтром, а «вместе по всем маркетплейсам»
считается в штуках — они складываются без всякого курса.

Для вопроса «сколько всего» в разделе продаж есть режим **«Всё в евро»** по
справочным курсам ЕЦБ (`scripts/collect_fx_rates.py`), понедельно. Он подписан
как оценка и с Seller Central не сойдётся — это ориентир масштаба.

**Настройки** — кнопка в правом верхнем углу на всех страницах: язык
(українська / русский / English), часовой пояс и тема. Пояс применяется к
отметкам времени, но не к календарным датам.

## Локальный запуск

```bash
python3 -m http.server 8000
```

ES-модули и WebCrypto требуют http — с двойного клика по файлу не заработает.

Проверка раздела без браузера:

```bash
npm i jsdom
node tools/mount-check.mjs weekly-sales
node tools/mount-check.mjs wiki
node tools/shell-check.mjs
node tools/numbers-check.mjs
```
