Указатель по репозиторию дашборда. Факты и найденные подвохи — в

## Что это

Amazon CRM на GitHub Pages: **https://oleh-hoff.github.io/**
Страница входа, оболочка с меню слева и рабочей областью справа, сбор данных
из SP-API кроном каждые 4 часа. Всё на ресурсах GitHub, без внешних хостингов.

Приватный репозиторий со скриптами и кредами — `../less1`.

## Стек: без сборки, и это принципиально

Чистый JavaScript с ES-модулями и CSS. **Ни React, ни Tailwind, ни шага
сборки.** Коммит сразу становится сайтом именно потому, что собирать нечего —
Pages отдаёт файлы как есть.

Компоненты 21st.dev (ориентир по дизайну) написаны на React + Tailwind и
вставляются не как код, а как решения: композиция, отступы, типографика,
состояния. Миграция на React обсуждалась и отклонена — предлагать её не нужно.

## Как добавить раздел

1. Файл в `assets/js/views/`, экспорт `{ titleKey, leadKey, mount(view, controls) }`
2. Строки на три языка в `assets/js/strings-crm.js` через `extendDict`
3. Строка в `ROUTES` файла `assets/js/app.js`
4. Пункт `<a class="nav-item">` в `app.html`

`mount` возвращает функцию уборки — в ней уничтожаются графики, иначе при
переключении разделов накапливаются подписки на изменение размера.

## Проверка перед коммитом

Браузера в среде нет, поэтому проверка — монтаж в headless-DOM. Без него
«синтаксис в порядке» ничего не значит: половина ошибок здесь появлялась
именно при отрисовке.

```bash
node --input-type=module --check < assets/js/app.js   # синтаксис
python3 -m py_compile scripts/*.py                    # сборщики
python3 -m http.server 8000                           # локальный просмотр
```

Плюс сверка словарей: все три языка должны иметь одинаковый набор ключей, а
каждый используемый ключ — существовать. Ключи вида `cat.${x}` собираются в
коде и регулярным выражением не находятся — их в проверке перечисляют руками.

## Три правила, выведенные из ошибок

**Статус не должен врать.** Флаг «выгрузка завершена» дважды выставлялся не
тем событием и прятал полугодовую дыру в данных. Если поле означает полноту
истории — оно не должно меняться от того, что короткий добор дошёл до конца
своего окна.

**Отсутствие данных ≠ сбой.** Amazon отменяет отчёт (`CANCELLED`), когда
возвращать нечего, и присылает статус `NONE` у показателя без данных.
Трактовать это как ошибку — значит пугать пользователя на пустом месте.

**Недоступное показывать, а не прятать.** Шесть из одиннадцати проверок
аккаунта через API невозможны. Они выведены с пометкой и причиной: скрытая
проверка создаёт впечатление, что аккаунт проверен целиком.

## Что публично

Репозиторий публичный — иначе Pages на тарифе Free не работает. Значит
`data/*.json` открыт по прямой ссылке любому, и форма входа его не защищает.
Пользователь об этом предупреждён дважды и принял решение осознанно.

В `data/` кладутся только агрегаты. Идентификаторы заказов, имена и адреса
покупателей туда попадать не должны.

Секреты SP-API лежат в Actions secrets — они закрыты даже в публичном
репозитории и недоступны рабочим процессам из форков.
